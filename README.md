## หลักการสำคัญที่โค้ดบังคับใช้ (ห้ามละเมิดในเฟสถัดไป)

1. **ไม่นับงบซ้ำ** — โคกหนองนา/จปฐ. เป็นโครงการย่อยในงบยุทธศาสตร์ ระบบดึงเฉพาะมิติเสริม
   (จำนวนแปลง, ค่าควบคุมงาน) มา join ด้วยชื่ออำเภอ/project_no — มี unit test ยืนยันว่า
   ยอดรวมจังหวัดไม่เปลี่ยนไม่ว่าจะมีหรือไม่มีไฟล์มอนิเตอร์
2. **#REF! ไม่พังเงียบ** — หมวดงบจังหวัด/กลุ่มจังหวัด (เสียหายทั้ง 2 ไตรมาสในไฟล์จริง)
   ถูกแยกออกจากยอดรวมและแจ้งเตือนชัดเจน ไม่แสดงเป็นเลข 0
3. **Anomaly ติด flag อัตโนมัติ** — %เบิกจ่าย > 100 หรือคงเหลือติดลบ = "ข้อมูลควรตรวจสอบ"
   (พบจริง 12 อำเภอในงบยุทธ ไตร 3-4 รวมถึงกุสุมาลย์ 295.9%)
4. **ชื่ออำเภอสะกดเพี้ยนถูก normalize** — "กุุสุมาลย์/เต่่างอย/โคกศรีีสุพรรณ" (สระซ้ำ) join เข้าอำเภอถูกต้อง
5. **คะแนนคุณภาพตรวจทานกับเกณฑ์** — พบจริง 1 อำเภอ (พังโคน: ไฟล์ให้ 3 แต่เกณฑ์คำนวณได้ 2)
   ระบบแสดงคะแนนตามไฟล์ แต่ติด flag "คะแนนไม่ตรงเกณฑ์" ให้ตรวจสอบ
6. **หน้ารายโครงการแสดงทุกโครงการจริง (92 โครงการ/กิจกรรม)** — แกะจากบล็อกรายโครงการ
   ในชีตยุทธ 3 ชีต, dedupe ข้ามชีตด้วยเลขที่โครงการ (พบเลขที่ 52 ซ้ำ 2 ชีตจริง — นับครั้งเดียว)
7. **คำตอบเรื่อง "เบิกเกิน 100%"** — ข้อมูลรายโครงการทั้ง 628 แถวไม่มีแถวใดเบิกเกินจัดสรรเลย
   การเกิน 100% เกิดเฉพาะใน "ตารางสรุป" ของชีตไตร 3-4 ที่ยอดจัดสรรไม่ sync กับรายโครงการ
   (เช่น กุสุมาลย์เบิก 615,485 = ตัวเลขของเมืองสกลนครเป๊ะ — น่าจะ copy-paste ผิดแถว)
   → อำเภอที่มีตัวเลขแบบนี้ขึ้นสถานะม่วง "ข้อมูลควรตรวจสอบ" แทนสีเขียว

## ฟีเจอร์ใหม่ (เพิ่มตามคำแนะนำผู้เชี่ยวชาญ 22 ก.ค. 69)

หลังนำเสนอ Prototype เฟส 1 ให้ผู้เชี่ยวชาญดู ได้เพิ่ม 7 ฟีเจอร์ต่อไปนี้ (ยังเป็น mock/inferred data
ระดับ prototype เช่นเดิม — ไม่ใช่เฟส 2 ETL จริง):

1. **ตัวชี้วัดต่อโครงการ** (`kpi.dept`/`kpi.province`) — กรอบตัวอย่าง (จำลอง) แยกกรมวัด/จังหวัดวัด
   ต่อโครงการ (ติดป้าย "ตัวอย่างกรอบตัวชี้วัด (จำลอง)" เสมอ ไม่ใช่ตัวชี้วัดจริงที่กรมประกาศ)
2. **เมนู 🗂️ กลุ่มงาน** — จัดกลุ่ม 92 โครงการตาม 4 กลุ่มงานจริงของสำนักงาน โดย `inferWorkGroup()`
   เทียบ keyword กับชื่อโครงการ — โครงการที่ไม่มี keyword ตรงจะ fallback + ติดป้าย "(อนุมาน)" เสมอ
3. **ช่องแนบเอกสาร PDF ที่ผู้บริหารอนุมัติ** — ปัจจุบัน seed ไม่มีไฟล์จริง จึงแสดง placeholder
   "ตัวอย่าง — ยังไม่ได้แนบไฟล์จริง" เสมอ (ห้ามสร้างเอกสารราชการปลอม) เฟสถัดไปแค่เติม `attachment_url`
   ในข้อมูลต้นทาง ระบบจะใช้งานได้ทันที
4. **ระบุระดับดำเนินการ** (`level`: province/district/mixed) — คำนวณจาก key ใน `byDistrict` ที่มีอยู่แล้ว
5. **เมนู 📚 ระเบียบ/แนวทาง/คู่มือ** — `app/data/regulations.js` มี 4 รายการ "อ้างอิงจริง" (สืบค้นยืนยันแล้ว:
   ระเบียบกระทรวงการคลังฯ 2562, พ.ร.บ.จัดซื้อจัดจ้างฯ 2560, plan.cdd.go.th, legal.cdd.go.th) และ 7 รายการ
   "ตัวอย่างประกอบ (จำลอง)" — ทั้งสองประเภทแยกป้ายชัดเจนในหน้าจอเสมอ ห้ามปนกัน
6. **เมนู 🤖 ถาม AI** — ต้นแบบจับคู่คำสำคัญ (`matchQuery()`) ระหว่างคำถามภาษาพูดกับระเบียบ/ชื่อโครงการ
   ระบุชัดว่า "ยังไม่เชื่อมต่อ AI จริง" ไม่ใช่ NLP จริง
7. **เชื่อมโยงระบบ BPM กรมฯ** — การ์ด mock ในหน้ารายโครงการชี้ไปยัง `bpm.cdd.go.th` (มีอยู่จริง)
   แต่ระบุสถานะ "ตัวอย่าง — ยังไม่ได้เชื่อมต่อจริง" เสมอ (ต้องมีสิทธิ์เข้าใช้งานจริงของกรมฯ)

เพิ่ม Export Wizard คู่ขนาน **รายโครงการ** (`js/export-projects.js`) แยกจาก Export เดิม (รายอำเภอ×ประเภทงบ)

# เฟส 2 — คู่มือติดตั้ง ETL บน Google Apps Script

เอกสารนี้พาไปทีละขั้น ตั้งแต่ย้ายไฟล์ Excel ขึ้น Google Sheets จนได้ URL มาใส่ใน Dashboard
(ใช้เวลาประมาณ 20–30 นาที ทำครั้งเดียว)

## ขั้นที่ 1 — ย้ายไฟล์ Excel ขึ้น Google Sheets

1. เปิด [Google Drive](https://drive.google.com) ด้วยบัญชี Google Workspace ของสำนักงาน
2. ลากไฟล์ `2569 เปอร์เซนต์ ผลการเบิกจ่าย .xlsx` ขึ้นไปวางใน Drive
3. คลิกขวาไฟล์ → **เปิดด้วย → Google ชีต** → จากเมนู **ไฟล์ → บันทึกเป็น Google ชีต**
4. เปิดไฟล์ Google ชีตที่ได้ แล้วคัดลอก **Spreadsheet ID** จาก URL:
   `https://docs.google.com/spreadsheets/d/`**`<<< ส่วนนี้คือ ID >>>`**`/edit`
5. ⚠️ **สำคัญ:** ชื่อชีต (แท็บล่าง) ต้องคงคำสำคัญเดิมไว้ เช่น "ยุทธ...ไตร 1-2", "บริหาร...ไตร 3-4",
   "งบจังหวัด...", "โคกหนองนา", "จปฐ", "ประเมินที่ 1" — ตัวจับคู่ชีตใช้ keyword เหล่านี้
   (เปลี่ยนชื่อเล็กน้อยได้ ระบบทนทานต่อช่องว่าง/เลขต่างกัน)

## ขั้นที่ 2 — สร้างโปรเจกต์ Apps Script

1. ในไฟล์ Google ชีตนั้น ไปที่เมนู **ส่วนขยาย (Extensions) → Apps Script**
2. ลบโค้ดตัวอย่างทิ้ง แล้ววางโค้ดทั้งหมดจากไฟล์ [Code.gs](Code.gs)
3. แก้บรรทัดนี้ให้เป็น ID จริงจากขั้นที่ 1:
   ```javascript
   SOURCE_SPREADSHEET_ID: 'ใส่_SPREADSHEET_ID_ที่นี่',
   ```
4. กด **บันทึก** (ไอคอนแผ่นดิสก์)

## ขั้นที่ 3 — ทดสอบก่อนเปิดใช้ (สำคัญ อย่าข้าม)

1. ที่แถบเครื่องมือด้านบน เลือกฟังก์ชัน **`testAgainstSeedContract`** แล้วกด **เรียกใช้ (Run)**
2. ครั้งแรกระบบจะขอสิทธิ์ — กด "ตรวจสอบสิทธิ์" และอนุญาต (สิทธิ์อ่านชีตในบัญชีตัวเอง)
3. ดูผลใน **บันทึกการดำเนินการ (Execution log)** เทียบกับค่าที่ควรได้:
   - `budget rows` ≈ 135 แถว (รวมแถว #REF! และแถวรวม — Dashboard จะกรองต่อเอง)
   - `quality rows` = 18
   - `kokNongNa rows` = 10–11
   - `noise` ควรเห็นรายการอย่าง "เงินยืม 9300", "ค่าจ้าง 6900" — แปลว่าตัวกรองทำงาน
   - `errors` ควรว่าง (ถ้ามี ให้ดูชื่อชีตที่แจ้งแล้วเช็คว่า header มีคำว่า จัดสรร/เบิกจ่าย หรือไม่)

## ขั้นที่ 4 — Deploy เป็น Web App

1. กดปุ่ม **ทำให้ใช้งานได้ (Deploy) → การทำให้ใช้งานได้รายการใหม่ (New deployment)**
2. กดไอคอนเฟือง → เลือกประเภท **เว็บแอป (Web app)**
3. ตั้งค่า:
   - คำอธิบาย: `SNK-CD War Room ETL`
   - เรียกใช้ในฐานะ (Execute as): **ฉัน (Me)**
   - ผู้ที่มีสิทธิ์เข้าถึง (Who has access):
     - **ทุกคนในองค์กร (Anyone within [ชื่อองค์กร])** ← แนะนำ ถ้าผู้ใช้ล็อกอิน Google Workspace ของสำนักงานทุกคน
     - หรือ **ทุกคน (Anyone)** ถ้าต้องการให้เปิดได้โดยไม่ล็อกอิน (ข้อมูลจะเข้าถึงได้ด้วยลิงก์ — ปรึกษาผู้บริหารก่อน)
4. กด **ทำให้ใช้งานได้ (Deploy)** แล้วคัดลอก **URL เว็บแอป** (ลงท้ายด้วย `/exec`)
5. ทดสอบ: วาง URL ในเบราว์เซอร์ ควรเห็นข้อมูล JSON (ขึ้นต้นด้วย `{"budget":[...`)

## ขั้นที่ 5 — เชื่อม Dashboard

เปิดไฟล์ `app/js/config.js` ในโฟลเดอร์ Dashboard แล้วแก้:

```javascript
window.APP_CONFIG = {
  appsScriptUrl: 'https://script.google.com/macros/s/XXXXXXXX/exec'  // ← URL จากขั้นที่ 4
};
```

เปิด `app/index.html` ใหม่ — มุมบนจะเปลี่ยนจาก "ข้อมูลตัวอย่าง (seed data)" เป็น
"Google Sheets (อัปเดตอัตโนมัติผ่าน Apps Script)" และข้อมูลทั้งหมดมาจากชีตจริง

## การทำงานหลังติดตั้ง

- เจ้าหน้าที่การเงิน/อำเภอ **กรอกชีตแบบเดิมทุกประการ** ไม่มีขั้นตอนเพิ่ม
- Dashboard ดึงข้อมูลใหม่อัตโนมัติทุก 10 นาที (มี cache ฝั่ง Apps Script 5 นาที)
- ถ้าแก้ชีตแล้วอยากเห็นผลทันที: กดปุ่ม "↻ รีเฟรชตอนนี้" บน Dashboard
  หรือรันฟังก์ชัน `clearCache` ใน Apps Script
- แก้โค้ด Code.gs เมื่อไร ต้อง Deploy ใหม่ (Deploy → จัดการการทำให้ใช้งานได้ → แก้ไข → เวอร์ชันใหม่)

## สิ่งที่ ETL นี้ป้องกันให้อัตโนมัติ (ตรงกับกฎทอง 5 ข้อ)

| กฎ | กลไกในโค้ด |
|---|---|
| อ่านเฉพาะขอบเขตตารางที่มี header | `findHeader()` หา keyword จัดสรร/เบิกจ่าย ไม่ fix ตำแหน่งแถว |
| ไม่ดึงคอลัมน์แถมท้าย (วันโอนเงิน ที่ทดเลข) | `readCell()` อ่านเฉพาะคอลัมน์ที่ header ระบุเท่านั้น |
| ตัดแถวหมายเหตุ/เชิงอรรถใต้ตาราง | `isFooterRow()` หยุดอ่านเมื่อเจอ "หมายเหตุ/เกณฑ์การให้คะแนน/ลงชื่อ" |
| ทดสอบเทียบผลลัพธ์ที่ถูกต้อง | `testAgainstSeedContract()` + unit test 16 ข้อฝั่ง Dashboard |
| ชีตมอนิเตอร์ไม่สร้างแถวงบซ้ำ | โคกหนองนา/จปฐ ไหลเข้า enrichment เท่านั้น เข้าคอลัมน์ budget ไม่ได้เชิงโครงสร้าง |

**หมายเหตุการออกแบบ:** ETL ส่งข้อมูล "ดิบแต่สะอาดระดับโครงสร้าง" (รวมแถว #REF!/แถวรวม ตามจริง)
แล้วให้ validation layer ฝั่ง Dashboard ตรวจซ้ำอีกชั้น (defense in depth) — ผลคือ Dashboard
แสดง "ข้อมูลต้องตรวจสอบ" ได้เหมือนเฟส 1 ทุกประการ ไม่ว่าข้อมูลจะมาจาก seed หรือชีตจริง

## สิ่งที่ต้อง calibrate กับชีตจริงในเฟสนี้ (รอทำหลังย้ายชีตเสร็จ)

1. **มิติเสริมของ จปฐ.** (วันที่โอนเงินรายอำเภอ จากชีต `จปฐ` + `จัดเก็บจปฐ`) — โค้ดเตรียมจุดต่อไว้แล้ว
   จะเปิดใช้เมื่อเห็นตำแหน่งคอลัมน์จริงบน Google Sheets
2. **ตารางรายโครงการเต็มรูปแบบ** (ทุกเลขที่โครงการในชีตยุทธศาสตร์) — ต้องดูโครงสร้างคอลัมน์
   รายโครงการบนชีตจริงก่อน จึงจะเขียน parser ส่วนนี้ได้แม่นยำ
